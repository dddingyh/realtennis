# 手机球拍（卡通版）玩家说明

把手机当球拍：**挥一下手机 = 击球**，**挥拍的早晚决定球打向左还是右**，屏幕上一个大按钮控制**上网 / 回底线**。
角色会自己跑位，你只管“什么时候挥、怎么挥、站哪”。无需任何校准，打开就能玩。

## 1. 连接

1. 在电脑上打开卡通版游戏，控制方式选 **手机**，画面出现二维码和 6 位房间号。
2. 手机扫码（或打开 `…/cartoon/controller.html`，手动输入房间号）。**页面一打开就开始联网**，顶部状态栏始终显示：
   **① 信令 → ② 找主机 → ③ 点对点**，连通后显示“已连接 · 延迟 xx ms”。
3. 点大按钮 **开始**（iPhone 会弹出“动作与方向”权限，请点允许）→ 选 **左手 / 右手** → 可选的“挥两下试试” → 比赛。
4. 桌面调试（无手机）：地址后加 `&sim=1`（同一浏览器内测试再加 `&local=1`），用按钮 / 键盘生成合成传感器数据，数据走和真机完全相同的识别流程：
   数字键 `1–4` 直接挥 上旋/平击/切削/挑高，空格挥当前球路，`N` 上网/回底线，`P` 暂停。

## 2. 怎么拿手机

像握网球拍：握住手机**下端**，**屏幕是拍面，顶端是拍头**，拍头朝前略微抬起。往前挥，**球拍“碰到球”的瞬间 = 手机转得最快的瞬间**，游戏就是以这个瞬间为击球时刻。
请用腕带或握紧，别脱手。

```
        拍头（手机顶端）
          ╱
        ╱   屏幕 = 拍面
      ╱
   [握这里]
```

## 3. 时机决定方向（最重要）

球飞来时，角色会跑到位，系统有一个“最佳击球时刻”。你挥得**比它早**还是**晚**，决定球去哪：

```
右手正手：   早 ◄──── 准 ────► 晚
            球去左边  直线/中路  球去右边
（反手、左手持拍则左右镜像）

   |-140ms ........ 0 ........ +140ms|   在这个范围内：越早越往左，越晚越往右
   超过约 ±140ms：球被拉到很偏，容易出界、力量变弱
   超过约 ±240ms：挥空
```

- 每次击球后屏幕大字显示 **早 / 准！/ 晚** 和相差的毫秒数，加一个**左 / 右箭头**表示球去了哪边，以及 1–5 颗星的击球质量。
- 想打斜线就稍微早一点，想打另一边就稍微晚一点；想打中路就追求“准！”。
- 离球太远（跑不到位）、被逼到极限，质量会下降。

## 4. 各种球怎么挥

识别靠挥拍路径的**仰角**，不用特别标准，不确定时默认**上旋**：

| 球路 | 怎么挥 |
|---|---|
| 上旋 | 由低到高、向前上方“刷”过去（默认抽球） |
| 平击 | 水平、干脆、用力地向前抽 |
| 切削 | 由高到低向下“切”，轻切 = 小球 |
| 挑高 | 从下往上大幅“捞”，球飞得高 |

挥得越用力球越快（但越难控制）；很轻的挥拍也会被识别，只是球慢。
网前（上网状态）所有击球自动变成**截击**，高球会自动**高压**扣杀。
屏幕上的 **上旋 / 平击 / 切削 / 挑高** 小按钮：**按住**它再挥拍 = 强制这一拍用该球路（手机识别不准时的兜底）。

## 5. 上网 / 回底线

屏幕下方一个**巨大的按钮**，大拇指随时能按：

- 在底线时显示 **上网**：点一下，角色冲到网前（约 2.5 米处）。网前截击更快、角度更大，但怕被**挑高球**和**穿越球**，覆盖左右范围也小。
- 在网前时显示 **回底线**：点一下退回。
- 跑动需要约 1.2–1.6 秒（按钮显示“上网中… / 回防中…”，再点一次可反悔），时机不对会吃亏。
- 按钮的状态以游戏主机报告的位置为准；按下有一下轻震动和提示音。

## 6. 发球

轮到你发球时屏幕出现黄色提示条：

1. **挥拍抛球**：挥一下手机，球被抛起。
2. **再挥拍：发球！**：球升到**最高点**时再挥一次。越接近最高点越快越准；同样，早一点 / 晚一点决定发向哪个角。
- 提示条显示“准备发球…”时稍等，马上轮到你。
- 球抛起后太久没挥，球会被接住，可以重新抛（不罚分）。

## 7. 界面速览

顶部：连接状态 + 延迟 + 设置。第二行：谁发球、比分、暂停 ⏸。中间：最近一拍的反馈。
底部：球路按钮 / 声音 / 震动开关，以及大大的 **上网 / 回底线** 按钮。
手机应**竖屏**握持；横屏会有提示。比赛中屏幕保持常亮（支持时），页面不可滚动 / 缩放。

## 8. 挥拍时刻校正

不同手机、网络延迟不同，可能一直偏“晚”或“早”。设置（右上角 ⚙）里：

- **挥拍时刻校正**滑条：一直显示“晚” → 向右调（提前）；一直显示“早” → 向左调（延后）。每格 5 ms，范围 ±150 ms。
- **按最近平均值校正**：根据最近 12 次的平均早/晚一键校正（如果你是故意拉斜线打出的早/晚，这个平均值没有意义，请手动调）。
- 游戏电脑端的设置也可以调 `RemoteAdapter.setTimingOffset(ms)`（正数 = 把挥拍视为更早发生）。

## 9. 故障排查

| 现象 | 处理 |
|---|---|
| 页面提示需要 HTTPS | 传感器只在**安全页面（HTTPS）**开放。请通过部署在 GitHub Pages（`https://…`）的游戏扫码；局域网 `http://192.168.x.x` 不行（iOS / Android 都不行），`http://localhost` 仅限本机。 |
| iPhone 点“开始”没弹窗 / 提示未授权 | 设置 → Safari → “动作与方向访问”打开；或清除该网站数据后重新扫码。权限必须由点击触发，别刷新后直接进入。 |
| Android 没数据 | Chrome 地址栏左侧 → 网站设置 → “动作传感器”允许；省电模式可能降低采样率。 |
| 微信等 App 内置浏览器打不开 / 连不上 | 请用系统浏览器（Safari / Chrome）打开链接。 |
| 挑高和切削总是反的 | 设置 →“手机倾角方向反了”切到“反转”（部分 iOS 机型重力符号相反；默认 iPhone 已取反）。 |
| 走路 / 小幅晃手误触发 | 判定阈值较低（对休闲玩家友好），连续乱晃有“防抖”过滤，但很快的甩手仍可能被当成一次挥拍。 |
| 挥了没反应 | 看状态栏是否“已连接”；不是的话挥拍不会发送，屏幕会提示“未连接到游戏”。两次挥拍之间有约 0.4 秒冷却。 |
| 击球总偏早 / 偏晚 | 见第 8 节。 |
| iPhone 没有震动 | iOS Safari 不支持网页震动，静默降级（屏幕反馈 + 声音照常）。 |

### 连接状态说明

1. **信令**：电脑和手机分别连上 PeerJS 公共信令服务器 `0.peerjs.com`。电脑端一直显示“正在连接信令服务器…”→ 电脑访问不了该服务器。
2. **找主机**：手机通过房间号找到电脑。显示“找不到主机 / 主机无应答”→ 房间号不一致，或电脑端游戏页已关闭 / 刷新（刷新后房间号会变，需要重新扫码）。
3. **点对点（WebRTC/ICE）**：一直停在“正在打洞 / 失败”→ 两台设备打不通：
   - 确认手机和电脑在**同一个 Wi‑Fi**（不要一个用蜂窝网络）。
   - 路由器的 **AP 隔离 / 访客网络**会让同一 Wi‑Fi 下设备互相看不见，请换主网络，或让电脑连手机热点。
   - 优先使用国内可用的 STUN（`stun.miwifi.com`、`stun.chat.bilibili.com`），最后用 PeerJS 公共 TURN 中转兜底（延迟会明显变高）。
   - 电脑上的 VPN / 代理可能干扰 WebRTC，可暂时关掉再试。
4. 比赛中断线：手机会自动重连（页面显示“连接中断，正在重连”），断线期间的挥拍**不会补发**。电脑端刷新游戏页后房间号变化，需要重新扫码。

## 10. 诚实的局限

- **真机行为没有在本环境验证过**：iOS 权限弹窗流程、屏幕常亮（Wake Lock）、震动、真实传感器采样率与时间戳、重力符号约定（iOS 默认取反，是沿用旧版的假设）、真实挥拍的仰角分布，都只在代码层面按规范实现，没有用真手机测过。
- 识别准确率数据来自**合成 IMU 轨迹**（我们自己写的刚体挥拍模型），只是上限 / 回归保护，不是真实用户的准确率。真人的“上旋 / 平击 / 切削 / 挑高”分界很可能需要调（阈值在 `cartoon/src/controller/arcade_gesture.js` 的 `ARCADE`）。
- “击球时刻 = 角速度峰值”是近似；真实击球点可能比峰值早或晚几十毫秒，且因人而异，所以才有第 8 节的校正。
- 挥拍之前的“引拍”如果很快（角速度很大），可能被当成一次挥拍，正式挥拍落在冷却期内被吞掉。
- PeerJS 公共信令 / WebRTC 路径在本容器里无法联网，只用 `?local=1`（BroadcastChannel）测过同一份协议和逻辑。
- iPhone 没有震动；声音需要用户先点过“开始”才能播放。
